# harness/stress

This directory holds two things:

- The edit-stress workspace (`Cargo.toml`, `base/`, `mid/`, `app/`): three crates that
  `harness/stress.py`, `harness/rebuild.py`'s callers and others copy and edit against one warm
  daemon. Its `Cargo.toml` lists only those three as members.
- The stress corpus (below): small crates, each loading one compiler area, so a slowdown there
  shows on its own instead of drowning in a real project, as rustc-perf's stress benchmarks do.

## The stress corpus

`manifest.json` lists the crates (`{"version": 1, "crates": [{"name", "path", "what"}]}`, paths
relative to this directory); the bench harness reads it.

| Crate | Loads |
|---|---|
| `deep-vector` | type inference: one `vec!` of 135,000 untyped integer literals |
| `trivial-consts` | const lowering and evaluation: 6,000 libc-style `const` items plus a few real const fns |
| `trait-heavy` | trait solving: type-level Peano arithmetic, an inferred-index HList, a Diesel-shaped query builder |
| `deep-macro` | macro expansion: 1,500-deep recursion, a quadratic tt-muncher, a 12,000-pair invocation |
| `big-file` | parsing, spans and hashing: 18,000 small items in one 1.4 MB file |

Each crate is its own workspace (an empty `[workspace]` in its `Cargo.toml`), has no dependencies,
and has a `fn main` that asserts computed values, so a build that compiles but behaves wrong fails
when run. blaze's root `Cargo.toml` excludes `harness`, so none of them is a member of blaze's
workspace, and none is a member of the edit-stress workspace here.

The large sources are generated by `gen.py` and checked in (each under 1.5 MB):

```
python3 harness/stress/gen.py '{"mode": "write"}'   # regenerate
python3 harness/stress/gen.py '{"mode": "check"}'   # exit 1 if a checked-in file is stale
```

`big-file/edits.json` describes an incremental edit (`{"version": 1, "edits": [{"name", "what",
"path", "insert_before_line", "text"}]}`): `shift-top` inserts one line at the top of
`big-file/src/items.rs`, so every span below it moves by one line while the items stay the same.
`main` checks a line distance that holds before and after the edit.
