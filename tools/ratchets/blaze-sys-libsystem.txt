# The libSystem symbols blaze-sys imports on macOS (aarch64-apple-darwin, outside cfg(test)),
# one a row, `<name>  # <why, or the area that calls it>`, sorted by the name C gives it (nm
# shows each with a leading underscore, not written here). Linux has no list: there blaze-sys
# references no C-library symbol at all (D180, the no-C-library decision of 2026-11-20). A
# call of the cold table of crates/blaze-sys/src/macos.rs is not here: blaze-sys defines it
# and finds libSystem's by `dlsym` at its first call. A new import is a decision: add it with
# its reason; a gone one is removed. Checked by scripts/src/bin/sys_imports.rs (`check`,
# target macos) against a built rlib; `write` rewrites it, keeping each reason.
# Derived by reading the source on 2026-11-20 (the extern blocks compiled for macOS, each
# symbol called from code the rlib holds), to be regenerated by the script on its first run.
